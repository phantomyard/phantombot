# Testing — contributor invariants

Part of the phantombot contributor guide: suite isolation from the developer's real HOME and live stores. The index of every invariant is in [`/AGENTS.md`](../../../AGENTS.md). Numbers are stable identifiers — code comments and tests cite them — so a new rule takes the next free number and nothing is renumbered or reused (the one-time renumbering into 71–73 and 77 is recorded in AGENTS.md). Each rule records a real incident; a deliberate, documented trade-off is not a defect.

## Invariants

<a id="inv-60"></a>
### 60. The test suite never runs with the developer's real HOME.

`tests/install-sh.test.ts` spawned `install.sh` with `...process.env`, and install.sh appends `# added by phantombot installer` plus a `/tmp/pb-install-*` PATH line to `$HOME/.bashrc` whenever the install dir is not on PATH. Every local run grew the owner's `.bashrc` (48 blocks on 2026-09-11, 12 more by 2026-09-17), and a leftover fake binary on PATH shadowed the real `phantombot`. The preload (`tests/testEnvIsolation.ts`) now sets `HOME` and `ZDOTDIR` to a throwaway dir UNCONDITIONALLY (`=`, not `??=`: HOME is always set, so respecting it is the bug); the real value survives only as `PHANTOMBOT_TEST_REAL_HOME` for guard tests. Tests that spawn scripts which edit rc files ALSO pass an explicit per-run `HOME`/`ZDOTDIR`/`SHELL`, so they stay safe if run without the preload. Tests: `tests/install-sh.test.ts` (rc write lands in the sandboxed home exactly once across two runs; suite HOME is under the isolation root), proven by mutation and by running main's test against a checksummed real `.bashrc`.

<a id="inv-72"></a>
### 72. Test runs never touch a live install's stores, and orphaned tasks are terminal, not retried forever (issue #632).

Two halves from the same incident class (the robbie host: a `bun test` run from a dev checkout rewrote the live `state.json`, and 23 task rows whose persona dir had vanished logged an error a minute for 34 days). **(a) The preload isolates ALL THREE XDG roots unconditionally** (`tests/testEnvIsolation.ts`): `??=` trusted an ambient root, but engine-scoped harness shells (`scopedChildEnv`, `src/lib/engineScope.ts`) inject `XDG_CONFIG_HOME`/`XDG_DATA_HOME`/`XDG_STATE_HOME` into every child — so `bun test` from inside a harness turn pointed the whole suite at the embedding application's live root. `XDG_DATA_HOME` only got unconditional treatment for `HOME` before; now all three are `=`, the real values survive as `PHANTOMBOT_TEST_REAL_XDG_*_HOME`, and `PHANTOMBOT_STATE` / `PHANTOMBOT_STATE_AUDIT` / `PHANTOMBOT_ENGINE_SCOPE` are cleared outright (an ambient `PHANTOMBOT_STATE` outranks the isolation root for `state.json`). **(b) One guard for every persistent store**: `assertTestWritable` (`src/lib/testGuard.ts`) is called from `openTaskStore`, `openMemoryStore`, `openPersonaVault`, `createPersona`'s dir creation and `writeConfigToml`; `state.ts`'s older `assertNotLiveStateWrite` is now a wrapper over it. Inert unless the preload armed `PHANTOMBOT_TEST_ISOLATION_ROOT`; `:memory:` and anything under the isolation root or tmpdir pass. **(c) The runtime stops CREATING orphans**: `resolveTaskPersona` validates the RESOLVED persona for the row-creating commands (`add`, `selftest`) — a broken default exits 2 with no row, and the error tells the user to pass `--persona` or run `phantombot persona switch`; read commands (`list`/`show`/`cancel`/`log`) deliberately skip the check so an orphaned queue stays cleanable. **(d) Tick deactivates a due task whose persona dir is missing** (`deactivateOrphaned`: `active = 0` + a `task_runs` row with the reason; `run_count` is NOT bumped — the task never ran), logged once at warn. **(e) Doctor makes any survivor visible**: the `orphaned_tasks` section scans every active task (`TaskStore.allActive`) for a missing persona dir, WARNs with the ids, deactivates them under repair, and unrepaired orphans fail the CLI exit code. Tests: `tests/test-env-isolation.test.ts`, `tests/test-env-isolation-subprocess.test.ts` (spawns `bun test` with all three XDG vars pointed at a fake-live dir before the preload and asserts it stays byte-identical — fails on the old `??=` preload), `tests/cli-task.test.ts`, `tests/cli-tick.test.ts`, `tests/cli-doctor.test.ts`.
